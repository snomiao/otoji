# 2026-05-14 ASR モデル精度・ノイズ耐性ベンチマーク

`sherpa-onnx` 経由で利用可能な複数 ASR モデルを、実音声 (FLEURS) および
人工的に背景雑音を重畳したクリップで評価し、`otoji` の既定 STT モデル選定
根拠を整理する。

## 1. 評価対象モデル

ASR ファミリー横断で 7 バリアントを比較した。すべて `sherpa-onnx-v1.13.2`
の `sherpa-onnx-offline` バイナリで実行している。

| 略称 | アーキテクチャ | サイズ | 公開元 |
|---|---|---|---|
| `sense-voice 2024-07-17 int8` | SenseVoice-Small | 155 MB | [FunAudioLLM](https://huggingface.co/FunAudioLLM/SenseVoiceSmall) |
| `sense-voice 2025-09-09 int8` | SenseVoice 再学習版 | 158 MB | 同上 (ONNX 再変換) |
| `sense-voice funasr-nano int8` | FunASR Nano | 178 MB | [FunAudioLLM/Fun-ASR-Nano-2512](https://huggingface.co/FunAudioLLM/Fun-ASR-Nano-2512) |
| `whisper-turbo` | Whisper large-v3 turbo | 537 MB | [openai/whisper-large-v3-turbo](https://huggingface.co/openai/whisper-large-v3-turbo) |
| `whisper-large-v3` | Whisper large-v3 | 1018 MB | [openai/whisper-large-v3](https://huggingface.co/openai/whisper-large-v3) |
| `zipformer-ja-en-reazonspeech` | Zipformer transducer | 417 MB | ReazonSpeech-K2 |
| `dolphin-{small,base} int8` | Dolphin CTC | 76–182 MB | DataoceanAI Dolphin |

## 2. 試験データ

### 2.1 クリーン音声

[`google/fleurs`](https://huggingface.co/datasets/google/fleurs) test split
を採用。各言語 30 サンプル (合計 120 クリップ) を `random.seed(42)` で抽出。
原音は 16 kHz mono float WAV。

| 言語コード | sherpa 言語フラグ | サンプル数 |
|---|---|---|
| `en_us` | `en` | 30 |
| `ja_jp` | `ja` | 30 |
| `cmn_hans_cn` | `zh` | 30 |
| `ko_kr` | `ko` | 30 |

### 2.2 雑音重畳音声

[ESC-50](https://github.com/karolpiczak/ESC-50) の環境音から下記カテゴリを
抽出し、FLEURS 各クリップに RMS 基準で SNR 制御を施した上で混合。

| シナリオ | 重畳カテゴリ | 目標 SNR |
|---|---|---|
| `clean` | (なし) | – |
| `office` | `keyboard_typing`, `clock_tick`, `footsteps`, `coughing` | 10 dB |
| `train` | `train`, `engine`, `crackling_fire` | 5 dB |

各シナリオ 60 クリップ (15/言語 × 4 言語) を生成。

### 2.3 評価指標

- **CJK** (ja / zh / ko): 文字レベル誤り率 (CER) — 句読点と SenseVoice 系
  メタトークン (`<|...|>`) を除去後 Levenshtein 距離 / 参照長
- **en**: 単語レベル誤り率 (WER) — 同様にトークン除去後の空白分割

## 3. クリーン音声における結果

```
順位  variant                                         overall    ja     en     zh     ko    avg ms
 1   sense-voice-zh-en-ja-ko-yue-int8-2024-07-17       8.7%    9.1    9.4    7.1    9.3      713
 2   whisper-large-v3                                 18.1%   13.6    6.2   27.8   21.6    12026
 3   whisper-turbo                                    18.3%   13.6    5.8   29.2   21.5     4817
 4   sense-voice-funasr-nano-int8-2025-12-17          21.0%   14.9   17.1    9.9   37.0      762
 5   dolphin-small-ctc-multi-lang-int8-2025-04-02     27.5%   19.5   99.9   10.6   11.5      700
 6   dolphin-base-ctc-multi-lang-int8-2025-04-02      31.1%   18.0   98.8   13.7   22.8      332
 7   zipformer-ja-en-reazonspeech-2025-01-17          79.7%   11.6   23.4  181.1  103.4      769
```

(`avg ms` は 1 クリップあたりの推論時間 / Apple M2、4 スレッド)

### 言語別最良 / 次点

| 言語 | 1 位 | 2 位 |
|---|---|---|
| en | `whisper-turbo` (5.8%) | `whisper-large-v3` (6.2%) |
| ja | `sense-voice 2024` (9.1%) | `zipformer-ja-en` (11.6%) |
| zh | `sense-voice 2024` (7.1%) | `funasr-nano` (9.9%) |
| ko | `sense-voice 2024` (9.3%) | `dolphin-small` (11.5%) |

### 主な所見

1. `sense-voice 2024-07-17 int8` が全 4 言語で 1 位ないし 2 位を維持し、総合
   8.7 % という他バリアントの倍以上の精度を実現した。
2. `2025-09-09` 再学習版は ja 76.8 %、ko 67.1 % まで悪化しており、訓練データ
   が中国語寄りに偏った疑いが強い。zh は 7.5 % と高水準を保つ。
3. Whisper 系は en で 6 % 前後と他を圧倒する一方、zh では 27–29 % と振るわ
   ない。`--whisper-language=zh` でも繁体字寄りの出力傾向が見られる。
4. `whisper-large-v3` と `whisper-turbo` の精度差は 0.2 pt 以下。turbo は
   2.5 倍高速 (4.8 s vs 12 s/clip) で、large-v3 を採用する積極的理由はない。
5. Dolphin は zh / ja / ko で 10–22 % と健闘するが、en で 99 % 超の出力崩壊
   を起こす (英語は対応外と推察)。
6. `zipformer-ja-en-reazonspeech` は ja で 11.6 % と高精度だが、学習対象外
   の zh / ko で 100 % を超える挿入誤りが出るため汎用用途には不可。
7. int8 量子化版と fp32 版の精度差はほぼ無く、推論速度は int8 が約 25 %
   速い。実運用は int8 一択。

## 4. ノイズ環境下での結果

クリーン bench で上位を占めた 4 バリアントを対象に、上記 `office` / `train`
シナリオを加えて再評価した。

```
variant                                       clean     office     train    Δoffice  Δtrain
sense-voice-zh-en-ja-ko-yue-int8-2024-07-17    9.7%     11.8%      12.1%      +2.1     +2.4
whisper-turbo                                 21.0%     21.9%      22.1%      +0.9     +1.1
sense-voice-funasr-nano-int8-2025-12-17       21.1%     22.8%      25.2%      +1.7     +4.1
dolphin-small-ctc-multi-lang-int8-2025-04-02  29.6%     29.3%      29.5%      -0.3     -0.1
```

### 主な所見

1. `sense-voice 2024` は両ノイズ条件下でも他バリアントの **半分以下** の誤り
   率を維持し、絶対精度で依然として最良である。
2. **Whisper-turbo はノイズ耐性が最も高い** (劣化幅 +1 pt 程度)。Whisper の
   学習コーパスに含まれる多様な録音条件が寄与していると考えられる。
3. `funasr-nano` は train シナリオで +4 pt と最も劣化が大きく、低 SNR 環境
   での運用には不向き。
4. Dolphin の劣化幅が小さいのは、`clean` 段階で既に英語が崩壊しており
   ceiling 効果が働いているためで、頑健性ではない。

## 5. 結論と otoji への反映

- **既定 STT モデル**: `sherpa-onnx-sense-voice-zh-en-ja-ko-yue-int8-2024-07-17`
  を採用 (`lib/otoji/src/config.rs::DEFAULT_SHERPA_VARIANT`)。
- **設定パネルの推奨表記**: 同モデルを「推奨・bench 最高精度・最速」とし、
  `2025-09-09` を「中文寄り・ja/ko 弱」と注記する。
- **英語ヘビーなユーザー向け選択肢**: `whisper-turbo` を案内可能にする。
  ただし PTT 用途には 4.8 s/clip は実用上厳しく、リアルタイム処理は
  SenseVoice 維持を推奨。
- **削除候補**: dolphin / zipformer は専用用途以外では採用しない。

## 6. 再現手順

```bash
# 1. ASR バイナリ + モデル
~/work/sensevoice-bench/sherpa-onnx-v1.13.2-osx-arm64-shared/bin/sherpa-onnx-offline
~/.cache/otoji/sherpa-onnx-*/

# 2. FLEURS test split (4 lang × 16 kHz float WAV)
hf download google/fleurs --repo-type dataset \
  --include "data/{en_us,ja_jp,ko_kr,cmn_hans_cn}/test*" \
  --include "data/{en_us,ja_jp,ko_kr,cmn_hans_cn}/audio/test*" \
  --local-dir /tmp/fleurs-test

# 3. ESC-50 (環境音)
curl -fL https://github.com/karolpiczak/ESC-50/archive/refs/heads/master.tar.gz \
  | tar -xz -C /tmp/esc50 --strip-components=1

# 4. ベンチ実行
python3 ~/work/sensevoice-bench/run_fleurs_bench.py   # SenseVoice 6 variants
python3 ~/work/sensevoice-bench/run_extra_bench.py    # + Whisper / Zipformer / Dolphin
python3 ~/work/sensevoice-bench/run_noise_bench.py    # + office / train シナリオ
```

ハードウェア: Apple M2 (8 コア) / macOS 25.5.0 / sherpa-onnx v1.13.2
シード: `random.seed(42)` (FLEURS サンプリング・ノイズ選択)
